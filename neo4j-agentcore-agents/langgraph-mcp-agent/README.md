# Neo4j MCP LangGraph Agent

A LangGraph ReAct agent that answers natural language questions about a Neo4j graph database. The agent reaches Neo4j through an AWS Bedrock AgentCore Gateway and reasons with Claude on Bedrock.

## Core Features

- **Neo4j over MCP**: graph queries (`get-schema`, `read-cypher`) are exposed as Model Context Protocol tools, so the LLM can explore and query the graph on its own.
- **AgentCore Gateway**: the agent talks to one secure HTTPS endpoint. The Gateway fronts the Neo4j MCP server running on AgentCore Runtime.
- **OAuth2 machine auth**: the agent authenticates to the Gateway with a Cognito client-credentials token, refreshed automatically before it expires.
- **Claude on Bedrock**: reasoning runs on a Bedrock-hosted Claude model through the Converse API. No model keys to manage; AWS credentials come from the standard chain.
- **SageMaker Unified Studio ready**: notebooks and an inference-profile helper let the same agent run inside a SageMaker Studio project.

## Quick Start

```bash
# 1. Install dependencies
uv sync

# 2. Get gateway credentials from the MCP server deployment
cp ../../neo4j-agentcore-mcp-server/.mcp-credentials.json .

# 3. Ask a question
./agent.sh "How many aircraft are in the database?"

# Or run the built-in demo questions
./agent.sh
```

That is it. The agent loads credentials, refreshes the token if needed, connects to the Gateway, and answers.

## High-Level Architecture

```
You ──question──▶ LangGraph Agent ──reasoning──▶ Claude (Bedrock)
                        │
                        │ MCP tool calls over HTTPS + OAuth2
                        ▼
                AgentCore Gateway
                        │
                        ▼
            Neo4j MCP Server (AgentCore Runtime)
                        │
                        ▼
                   Neo4j database
```

Two separate credential systems are in play:

- **OAuth2 (Cognito)** authenticates the agent to the Gateway.
- **AWS credentials** authenticate the agent to Bedrock for the Claude model.

## How It Works (ELI5)

- **The agent is a loop.** It asks Claude "what should I do?", Claude either answers or asks to run a tool, the tool runs, and the result goes back to Claude. This repeats until Claude has the final answer. That loop is the "ReAct" pattern, and LangGraph runs it.
- **Tools come from the graph, not hardcoded.** On startup the agent asks the Gateway "what tools do you have?" and gets back Neo4j tools like "read the schema" and "run a Cypher query." Claude decides when to call them.
- **The Gateway is a doorway.** Instead of the agent knowing where Neo4j lives, it knows one URL. The Gateway checks the agent's token, then forwards tool calls to the Neo4j MCP server and returns the results.
- **Tokens expire, so the agent renews them.** The production agent checks the token's expiry on every run. If it is within 5 minutes of expiring, the agent gets a fresh one from Cognito and saves it back to `.mcp-credentials.json`.
- **Two ways to run it:**
  - Production agent (`./agent.sh`): refreshes the OAuth2 token automatically. Use for anything long-running.
  - Simple agent (`uv run python -m neo4j_mcp_agent.simple_agent "..."`): uses the static token from the file. Good for a quick one-off; the token lasts about an hour.

## Configuration

| Setting | Where | Default |
|---------|-------|---------|
| Model | `MODEL_ID` in `neo4j_mcp_agent/core.py` | `global.anthropic.claude-haiku-4-5-20251001-v1:0` |
| Region | `region` in `.mcp-credentials.json` | Falls back to `DEFAULT_REGION` in `core.py` (`us-east-1`) |
| Credentials | `.mcp-credentials.json` at the project root | Generated by the MCP server's `./deploy.sh credentials` |

## SageMaker Unified Studio

SageMaker Unified Studio blocks direct Bedrock model access through a permissions boundary. The workaround is a Bedrock application inference profile carrying the `AmazonBedrockManaged=true` tag. Create one, then paste the ARN into the notebook config cell:

```bash
./inference-profiles/setup-inference-profile.sh --list        # Show profiles and tag status
./inference-profiles/setup-inference-profile.sh haiku         # Create a haiku profile
./inference-profiles/setup-inference-profile.sh --test haiku  # Create and test
```

| Notebook | Purpose |
|----------|---------|
| `notebooks/minimal_langgraph_agent.ipynb` | LangGraph + Bedrock smoke test |
| `notebooks/neo4j_simple_mcp_agent.ipynb` | Simple MCP agent over the Gateway |
| `notebooks/neo4j_strands_mcp_agent.ipynb` | Strands MCP agent over the Gateway |

See [docs/SAGEMAKER-MODELS.md](docs/SAGEMAKER-MODELS.md) and [docs/IAM.md](docs/IAM.md).

## Testing

```bash
uv sync --extra test
uv run python tests/test_fastmcp.py
```

`test_fastmcp.py` lists the Gateway tools and calls `get-schema` and `read-cypher` directly with the FastMCP client. No LLM involved, so it is the fastest way to confirm the Gateway and Neo4j are reachable.

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| `Token refresh failed: 401` | Wrong `client_id` / `client_secret` in `.mcp-credentials.json` |
| `NoCredentialsError` | AWS credentials not configured (`aws configure` or env vars) |
| `AccessDeniedException` on the model | Enable Claude model access in the Bedrock console |
| `httpx.ConnectError` | Wrong `gateway_url`, or the MCP server is not deployed |
